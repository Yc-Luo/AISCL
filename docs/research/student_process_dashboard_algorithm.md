# 学生端小组协作学习状态面板算法说明

版本：`process_goal_shared_regulation_v2`

适用页面：学生端“小组协作学习状态面板”

算法定位：形成性学习反馈算法，不作为终结性评价、成绩评定或个人排名依据。

## 1. 设计原则

本算法服务于人智协同小组协作学习过程反馈，目标是帮助学习者理解当前小组在“问题建构、意义探索、解释整合、应用解决”过程中的学习质量，并获得下一步共享调节建议。

算法遵循四个原则：

1. 平台行为不直接等于学习质量。点击、打开、发言、上传等行为只作为过程证据来源。
2. 重复行为需要合并和封顶。同一类高频操作不会线性推高目标表现。
3. 目标状态必须由证据链支撑。核心关注“问题、观点、证据、解释、修订、应用”的结构质量。
4. 建议面向小组共享调节。反馈不评价个人、不排名、不使用惩罚性语言。

## 2. 理论映射

算法由三类研究基础指导：

1. 人智协同学习目标：问题建构清晰性、证据判断可靠性、观点比较合理性、解释修订开放性、迁移应用适切性。
2. 协作知识建构过程：问题建构、意义探索、解释整合、应用解决。
3. 共享调节机制：目标调节、过程监控、策略协同、情绪协调。

前期机制分析中强调的情绪协调和动机因素不作为单独分数展示，而作为协作温度和共享调节建议的触发依据。例如，当小组出现低参与、沉默、互动停滞或支持性回应不足时，系统优先触发情绪协调或目标调节建议。

## 3. 数据来源

算法使用近 14 天的小组过程数据。

| 数据来源 | 用途 | 说明 |
| --- | --- | --- |
| 小组聊天 | 识别问题表达、理由表达、互动接续、情绪线索 | 仅学生消息计入参与，不让 AI 消息推高参与度 |
| 共享文档 | 识别共同成果、解释草稿、修订痕迹 | 文档存在不直接等于高质量 |
| 论证空间事件 | 识别问题、观点、证据、反方观点、反驳、关系线 | 是证据与观点结构的主要来源 |
| Wiki/知识沉淀 | 识别结构化观点、证据、阶段总结 | `verified` 证据可作为已核查证据 |
| 资源与素材事件 | 识别资料接触、证据绑定、素材转化 | 单纯打开资源为弱证据，绑定或转化为强证据 |
| 任务提交 | 识别应用解决和成果落地 | 只作为迁移应用线索之一 |
| 平台活动日志 | 合并资源接触、预览、上传等行为 | 重复行为按对象去重 |

## 4. 行为清洗规则

算法先将原始行为合并为过程证据，避免“行为分过高”。

### 4.1 去重

同一学生反复打开同一资源、预览同一文件或切换同一对象，只记为同一类资源接触证据。论证节点、证据来源、关系线、Wiki 条目等按 `node_id`、`source_id`、`resource_id`、`wiki_item_id`、`document_id` 等标识去重。

### 4.2 分层

行为被分为三层：

| 层级 | 示例 | 算法解释 |
| --- | --- | --- |
| 弱证据 | 打开资源、浏览页面、普通短消息 | 说明有接触，但不直接说明学习质量 |
| 中证据 | 提出问题、发表较完整理由、创建文档、添加观点节点 | 说明有学习行动 |
| 强证据 | 证据绑定来源、证据支持观点、形成反方观点、修订解释、说明适用边界 | 说明进入目标相关质量表现 |

### 4.3 封顶

所有计数型指标使用封顶函数：

```text
bounded(x, threshold) = min(1, x / threshold)
```

例如，聊天消息超过阈值后不再继续线性增加参与表现；资源打开次数如果没有转化为证据绑定、观点支撑或文档修订，也不能推高证据可靠性。

## 5. 五个目标的计算

每个目标输出 0 到 100 的状态值，但页面解释为过程状态，不解释为成绩。

水平标签规则：

| 分值区间 | 标签 |
| --- | --- |
| 75-100 | 良好 |
| 45-74 | 发展中 |
| 20-44 | 需加强 |
| 0-19 | 待开始 |

## 6. 目标一：问题建构清晰性

含义：小组是否明确核心问题、对象范围、关键条件和判断标准。

计算特征：

| 特征 | 权重 |
| --- | --- |
| 问题线索，如问句、问题节点 | 0.30 |
| 边界与标准表达，如对象、范围、条件、判断标准 | 0.25 |
| 问题建构阶段事件或共享文档建构 | 0.15 |
| 理由性表达，如因为、依据、证据、建议 | 0.15 |
| 成员参与覆盖与轮替回应 | 0.15 |

封顶规则：

1. 若没有问题线索，也没有边界或标准表达，最高 35 分。
2. 若参与成员覆盖低于 34%，最高 65 分。

## 7. 目标二：证据判断可靠性

含义：小组是否能够形成证据、绑定来源、核查证据，并说明证据与观点的关系。

计算特征：

| 特征 | 权重 |
| --- | --- |
| 证据数量，包括证据节点和证据类 Wiki | 0.20 |
| 来源绑定数量 | 0.25 |
| 证据核查比例 | 0.25 |
| 证据与观点关系比例 | 0.15 |
| 资料转化为证据或知识沉淀 | 0.15 |

核心公式：

```text
evidence_total = max(证据节点 + 证据Wiki, 来源绑定 + 证据Wiki, AI引用数)
checked_evidence = min(evidence_total, 来源绑定数 + verified证据Wiki数)
evidence_check_ratio = checked_evidence / evidence_total
```

封顶规则：

1. 若没有证据线索，最高 20 分。
2. 若有证据但没有已核查证据，最高 55 分。
3. 若只有资源打开而没有证据绑定或转化，最高 40 分。

## 8. 目标三：观点比较合理性

含义：小组是否呈现不同观点，并基于证据、理由、适用条件和局限进行比较。

计算特征：

| 特征 | 权重 |
| --- | --- |
| 观点数量 | 0.25 |
| 反方观点与反驳数量 | 0.25 |
| 论证关系线数量 | 0.20 |
| 比较性语言和理由性表达 | 0.20 |
| 证据基础 | 0.10 |

封顶规则：

1. 若没有观点，最高 20 分。
2. 若观点少于 2 个且没有反方观点，最高 45 分。
3. 若没有论证关系，也没有比较性表达，最高 65 分。

## 9. 目标四：解释修订开放性

含义：小组是否根据证据、同伴反馈或 AI 支架修订解释。

计算特征：

| 特征 | 权重 |
| --- | --- |
| 解释草稿或阶段总结 | 0.20 |
| 文档、节点或 Wiki 修订事件 | 0.30 |
| 批注回应、批注解决或反驳回应 | 0.20 |
| 已核查证据或反驳对修订的支撑 | 0.15 |
| 修订性语言，如修改、补充、完善、根据反馈 | 0.15 |

封顶规则：

1. 若没有文档或阶段总结，最高 25 分。
2. 若没有修订事件，最高 60 分。

## 10. 目标五：迁移应用适切性

含义：小组是否将解释或方案迁移到新情境，并说明适用条件、限制和边界。

计算特征：

| 特征 | 权重 |
| --- | --- |
| 方案、解决节点或应用阶段事件 | 0.30 |
| 小组任务完成或提交 | 0.20 |
| 应用、迁移、适用情境、限制等表达 | 0.25 |
| 阶段总结或论证空间快照 | 0.15 |
| 理由性表达 | 0.10 |

封顶规则：

1. 若没有方案线索，也没有任务提交，最高 30 分。
2. 若没有适用条件或迁移表达，最高 70 分。

## 11. 学习进程判断

学习进程包含四阶段：

1. 问题建构
2. 意义探索
3. 解释整合
4. 应用解决

阶段判断优先级：

1. 若教师端或实验配置明确设置当前阶段，优先使用配置阶段。
2. 若有阶段事件，使用近期阶段事件中出现最多的阶段。
3. 若无阶段事件，则根据过程证据推断：
   - 有应用事件、方案节点或任务提交，推断为应用解决。
   - 有修订、反方观点、反驳或论证关系，推断为解释整合。
   - 有证据、资料转化或观点，推断为意义探索。
   - 否则推断为问题建构。

阶段状态规则：

| 状态 | 含义 |
| --- | --- |
| `completed` | 前序阶段目标表现达到发展中及以上 |
| `in_progress` | 当前阶段已有过程证据或质量表现 |
| `needs_more` | 有少量证据但质量不足 |
| `pending` | 尚未出现明显证据 |

## 12. 证据与观点结构生成

结构包括五部分：

1. 核心问题
2. 主要观点
3. 支持/反对证据
4. 当前解释
5. 迁移应用

生成规则：

1. 核心问题优先从共享文档、Wiki 和学生对话中的问句提取。
2. 主要观点优先读取 `claim` 和 `controversy` 类型 Wiki；若无，则使用论证空间观点节点数量说明。
3. 证据状态由 `evidence_total`、`checked_evidence` 和 `unchecked_evidence` 生成。
4. 当前解释优先读取阶段总结 Wiki，其次读取最新共享文档摘要。
5. 迁移应用根据方案节点、应用阶段事件、任务提交和应用表达生成。

## 13. 下一步共享调节建议

页面每次只展示一个最优先建议。建议类型包括：

1. 目标调节
2. 过程监控
3. 策略协同
4. 情绪协调

触发规则：

| 建议类型 | 主要触发条件 |
| --- | --- |
| 情绪协调 | 参与成员少、消息少、互动停滞、支持性回应不足或消极表达较多 |
| 目标调节 | 问题建构清晰性低于 60 |
| 过程监控 | 证据判断可靠性低于 65，且已进入或接近意义探索 |
| 策略协同 | 观点比较低于 65，或解释修订低于 60 |

优先级说明：

情绪协调不会作为惩罚性评价展示。只有当小组已经形成基本问题线索但互动停滞时，才优先提示情绪协调；若问题本身仍不清楚，则优先提示目标调节。

## 14. 小组协作温度

协作温度用于轻量呈现协作状态，不评价个人贡献。

计算维度：

| 维度 | 权重 | 指标 |
| --- | --- | --- |
| 讨论参与度 | 0.30 | 参与成员比例、学生消息数、轮替回应 |
| 观点多样性 | 0.25 | 观点、反方观点、证据、想法节点 |
| 协作互动质量 | 0.25 | 论证关系、批注互动、修订、理由表达 |
| 情绪氛围 | 0.20 | 支持性表达与消极表达的平衡 |

情绪氛围计算：

```text
emotional = clamp(68 + 支持性表达次数 * 4 - 消极表达次数 * 10, 30, 90)
```

若近 14 天无学生消息，则情绪氛围设为 50，避免系统无依据地判断氛围好坏。

## 15. 论文声明建议

论文中可将该算法表述为：

本研究构建了一个面向形成性反馈的过程学习分析模型。该模型不将平台行为频次直接解释为学习质量，而是先对小组协作过程中的对话、文档、论证空间、知识沉淀、资源使用和任务提交等行为进行去重、封顶和证据分层，再将其映射到问题建构清晰性、证据判断可靠性、观点比较合理性、解释修订开放性和迁移应用适切性五个目标。模型进一步结合共享调节理论，从目标调节、过程监控、策略协同和情绪协调四个维度生成下一步协作建议。该算法定位为学习过程中的形成性反馈工具，不用于终结性评价或学生个体排名。

## 16. 局限

1. 该算法属于规则型过程分析模型，不能完全替代人工质性判断。
2. 情绪协调仅基于轻量语言线索和参与模式判断，不能推断个体真实情绪状态。
3. 若小组未充分使用论证空间、Wiki 或共享文档，部分目标可能因缺少可追踪证据而偏低。
4. 若后续研究需要更高解释精度，可在该规则模型基础上叠加人工编码样本校准、文本语义分类或学习序列模型。
